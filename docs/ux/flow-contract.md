# Контракт продуктового flow

Каркас одинаков для всех продуктов: универсальная страница `/v4/run/$productId/$step` ([`src/routes/v4.run.$productId.$step.tsx`](../../src/routes/v4.run.$productId.$step.tsx)) рендерит один из шагов из словаря `StepId` на основе `product.steps`.

## Словарь шагов (`StepId`)

| ID | Подпись |
| --- | --- |
| `scenario` | Сценарий |
| `source` | Источник |
| `combining` | Объединение |
| `metrics` | Метрики и фокус |
| `params` | Параметры |
| `check` | Проверка |
| `run` | Запуск |
| `result` | Результат |

Каждый продукт объявляет свой набор и порядок шагов в `products[].steps`. Новые шаги без явного требования не добавляем.

## Вход во flow

- Создание проекта (`/v4/projects/new`) → редирект на `/v4/run/$productId/source` с уже заполненным контекстом проекта.
- Из карточки проекта (`/v4/projects/$projectId`) можно вернуться к любому пройденному шагу.

## Динамический шаг «Объединение»

- Шаг `combining` есть в `products[].steps` только у продуктов с `supportsCombining: true` (сейчас — Конструктор дашбордов).
- В stepper шаг `combining` показывается **только если** в URL присутствует `?second=1` (пользователь явно добавил второй источник на шаге «Источник»).
- При одном источнике шаг скрыт — никаких «опционально», dashed-бордеров и подписей «(опц.)».
- Поисковые параметры (`?second=1`) пробрасываются через `Link` во всех переходах stepper и FlowActionBar.

## Шаги — что в них

### Сценарий (`scenario`) — только семантика

Выбор сценария: Консервативный, Сбалансированный, Охватный, Исследование, Кластеризация. Без слова «режим».

### Источник (`source`)

- Первый источник всегда обязателен. Способы — из `product.allowedSources`: загрузка файла, подключённый аккаунт, источник из Библиотеки, текстовая тема, URL.
- Подключённые аккаунты сгруппированы по системам (Яндекс Директ, Google Ads, …).
- Источник из Библиотеки можно искать и фильтровать.
- Если `product.supportsSecondSource: true` — кнопка «Добавить второй источник». Второй источник равноправен первому. Включение второго источника проставляет `?second=1` и делает шаг `combining` видимым.

### Объединение (`combining`)

- Карточка с двумя выбранными источниками (имя, строки, колонки).
- Диагностика совпадения: ключевые колонки, процент пересечения, количество дублей.
- Доступно только при двух источниках.

### Метрики и фокус (`metrics`) — Анализ кампаний

Выбор приоритетных метрик и сегментов внимания.

### Параметры (`params`)

Набор параметров продукта (например, для семантики — глубина, для BD Optimization — пороги).

### Проверка (`check`)

Сводка перед запуском: источники, параметры, ожидаемый результат, предупреждения. Кнопка действия — «Запустить» (не «Далее»).

### Запуск (`run`)

Состояние «Идёт обработка» с возможностью вернуться позже.

### Результат (`result`)

- Карточка результата с действиями: открыть результат, открыть Библиотеку, скачать (для Excel).
- Демо-кнопка показывается только у продуктов с `hasDemoDashboard: true` (сейчас — только Конструктор дашбордов).
- Никаких CTA «Открыть продукт» с финального шага.

## Перепрогон vs. новый проект

- Перепрогон обновляет **текущий результат проекта**.
- Чтобы сохранить снапшот — пользователь создаёт новый проект.
- Не вводим отдельные сущности «черновик», «запуск», «снимок» — они не нужны на уровне UI-контракта.

## Stepper и навигация

- Завершённые шаги кликабельны, активный — выделен, будущие — disabled.
- В stepper не показываются «технические» обозначения шагов («Шаг N из M», «опц.»).
- `FlowActionBar` всегда содержит «Назад» и «Далее: <следующий шаг>». На последнем шаге — `nextSlot` (без авто-«Готово»).
- При навигации `search`-параметры (`?second=1`) сохраняются.

## Что НЕ делаем во flow без явного требования

- Не добавляем новые шаги, статусы, тональности.
- Не добавляем сущности типа «черновик» или «запуск».
- Не меняем тексты продуктов — они зафиксированы в `perfops-v4-data.ts`.
- Не дублируем главную на странице «Продукты».
